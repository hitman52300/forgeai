ForgeAI optimizer policy (applied deterministically by app/optimization/optimizer.py;
LLM-written text only enters through prompts/critic.txt rules).

Per iteration the optimizer fixes at most the TWO most frequent failure categories.
Only the configuration fields mapped to that category may change:

retrieval_miss          -> retrieval_config.top_k (+3, max 12), retrieval_config.similarity_threshold
                           (-0.05, min 0.10); if top_k was already raised, chunk_size x0.7 (min 300)
                           with 15% overlap (new index; old index kept)
prompt_defect           -> extra_rules (+ critic rules)
hallucination           -> runtime_options.strict_numeric_grounding = true, extra_rules (+ critic rules)
wrong_refusal           -> similarity_threshold / refusal_policy.min_evidence_score (+/-0.05, direction
                           decided by which kind of wrong refusal dominates), extra_rules (+ critic rules)
tool_defect             -> attach a registry tool whose absence caused the failure (with justification),
                           extra_rules (tool-usage rule)
output_contract_defect  -> runtime_options.contract_retries (+1, max 3), extra_rules (schema rule)

Critic rules are rejected if they contain any expected fact or number from the evaluation
dataset (prevents answer leakage / overfitting to the test set).
The full dataset is re-run after every change so regressions are visible; the best
version (pass rate, then composite score) is kept.
